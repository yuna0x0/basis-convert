# 2026-08-31

Released, renamed, and fixed the first bug found by wearing the result.

## Shipped

`v0.1.0`, `v0.1.1` and `v0.1.2` are out, through three channels:

- **GitHub releases**, built by `.github/workflows/release.yml` on a version tag. Each carries
  the bare `package.json`, a VPM zip, a `.unitypackage` and a signed `.tgz`. Tests are excluded
  from the artifacts, the way Modular Avatar, NDMF and Avatar Optimizer keep theirs out of a
  consumer's project.
- **The VPM listing** at `vpm.yuna0x0.com`, which reads those releases.
- **OpenUPM**, tracking `githubRelease` so it republishes the signed tarball rather than
  building its own. `signed: true` on every version.

The docs site is live on GitHub Pages and rebuilds when `docs/**` or the package manifest
changes, so the version it quotes cannot go stale: pages write `{{VERSION}}` and a Docusaurus
markdown preprocessor fills it in from `package.json`.

## Renamed to Watari

"Basis Convert" was the shape the trademark policy warns about, a bare `Basis <Word>` used as a
product name, while descriptive reference is separately permitted. The product is **Watari**, and
`displayName` is `Watari (Converter for Basis)`; menus are `Tools > Watari > Convert Avatar to
Basis`. Decision 0002 records the reasoning and the ecosystem evidence: Haï leads with `HVR`,
towneh's package carries no mark at all, and a bare `Basis <Word>` from a third party appears
nowhere.

The package id, the namespaces and the assembly names did not change. They are not what a user
reads, `basis` is a scope segment rather than a product name, and changing the id would mean a
second OpenUPM entry and orphaning what was published.

The repository moved to `yuna0x0/watari-basis`, so every URL followed.

## The first bug found by wearing it

A converted avatar's toggles were inverted: turning `Tail_OFF` on showed the tail. Eight toggles
on the reference avatar, and the whole suite passed throughout.

The mapper knew which side of a toggle animated each object and kept only whether both had. The
planner then had to decide which side to fill with the avatar's authored state, and decided from
the value:

```csharp
activation.Choices[activation.Choices[1] ? 0 : 1] = authored;
```

**A clip that switches an object off leaves the same value behind as a side that animated
nothing.** So the authored state landed on the side that had animated, and every one-sided toggle
came out backwards. Blendshapes had the identical fault; material properties did not, because
they already recorded which side set each channel.

`SetWhenOff` and `SetWhenOn` are now recorded per activation and per blendshape, and the fill
moved into `VixxyAuthoredDefaults`, which is a pure function of those flags. That made both
halves testable without an avatar, which matters: most of this suite is gated on a purchased
avatar and silently skips for anyone else.

## Upstream

Switching the Basis project to Android to export an avatar broke its compilation:
`SMModuleGlobalIlluminationURP` is declared under `#if BASIS_HAS_GI && !UNITY_ANDROID`, and one
camera test used it under `#if BASIS_HAS_GI` alone. Thirty-one other guards in those two packages
use both conditions. Fixed upstream as BasisVR/Basis#1024.

## Next

1. **Multi-value selectors.** The "15 of 26 toggles never trace" figure was wrong, and so was
   the diagnostic message that produced it: it counted menu controls against traced parameters.
   The avatar's 26 toggle controls share **14 parameters**, of which **11 trace**. The three that
   do not are not failures: `F_Parts` drives a nine-state facial layer, `Hair` a five-state one,
   and `F_Set` is only steered inside the gesture layers, which are skipped on purpose. Several
   menu controls share one int parameter and each selects a value. Vixxy holds that natively as a
   control with several choices; the reader only understands two-state on/off layers.
2. **A fixture avatar.** Sixteen of twenty-five test files are gated on a purchased avatar and do
   nothing without it. `DynamicBoneChain.prefab` proves hand-authored fixtures work; this is the
   same idea at avatar scale, and needs a prefab with missing-script components plus a menu
   asset, an FX controller and clips.
3. **Modular Avatar `ObjectToggle`**, and gimmick controllers whose layers are steered by more
   than one parameter.
4. **Puppets onto Vixxy sliders**, and **ambient motion onto `BasisAuthoredMotion`**.
5. **Tuning the two jiggle heuristics**, which needs a person watching an avatar move.

## Watch out for

- **A headless test run needs the editor closed.** `unity test` exits 6 and writes no results
  when the project is locked, which reads like a failure but is not one.
- **A green run is still not proof the code compiled.** The runner checks the project log for
  `error CS` and deletes the results file first, because Unity keeps the last good assemblies and
  reports their results when compilation fails.
- **The docs site and the package version are linked.** Bump the version and the site redeploys;
  do not hardcode a version number in a page.
