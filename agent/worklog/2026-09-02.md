# 2026-09-02

Chased a blendshape that reset on a real avatar. It was not a bug, in this package or in Basis.

## The blendshape reset was a control default

`Body_base.Toe_heels` read 0 at runtime where the mesh is authored at 100. Traced the whole way
down:

- The avatar's `Boots_OFF` menu item drives parameter `Boots` at value 1, and `Boots_OFF.anim`
  sets `Body_base.Toe_heels` to 0. So the coupling is the avatar's, not ours.
- The converted Vixxy control holds `choiceValues [0, 1]` and `Toe_heels [100, 0]`, which is
  faithful: value 0 keeps 100, value 1 sets 0.
- Its `defaultValue` was 1, so Vixxy applied the second choice at load and wrote 0.

`defaultValue` was set by hand, through the button beside each choice in Vixxy's inspector
(`VLayoutSettings.cs:133`, the only code in the project that writes that field). Deliberate: a
different outfit was wanted at spawn. The toe shape came along with it because the source avatar
tied the two together.

**Our writer was never involved.** A fresh conversion writes `defaultValue=0` on all eleven
controls, and re-converting after setting them all to 1 by hand put all eleven back to 0:
`RemoveReplaceable` destroys the old components and the rewrite takes the parameter's declared
default. Verified end to end rather than reasoned about, after an earlier probe tested only the
fresh path and missed the one that mattered.

The fix is authoring, not code: drop the `Toe_heels` properties from that control, or set the
second choice to 100. Either way a re-conversion overwrites it, since the converter rebuilds from
a source that assumed the other outfit. Worth saying in the docs if it comes up again.

Detours worth keeping:

- `Toe_highheels` was the shape suspected for most of the day and was never involved. Nothing
  animates it and nothing we write touches it.
- The first watcher keyed on blendshape index and silently skipped renderers with fewer shapes.
  Searching by name found carriers the index version could not have.
- The runtime avatar is named from `BasisBundleLoadAsset`, so a generated id in the hierarchy
  means a bundle load rather than the scene object. That one line settles which path is running.

## SaveAsPrefabAsset fails hard, and only NDMF saves the build

`PrefabUtility.SaveAsPrefabAsset` on a hierarchy holding a missing script returns null and writes
no file: `missingBefore=3 success=False returnedNull=True fileExists=False`. It does not save and
drop them.

`BasisTemporaryStorageHandler.SavePrefabToTemporaryStorage` ignores the return and hands the build
its path anyway, so the bundle is built from a file that does not exist. What saves it is
`dev.hai-vr.basis.ndmf`, whose `OnBeforeBuildPrefab` hook strips missing scripts first, and that
hook is behind `BASISNDMF_NDMF_IS_INSTALLED`, a version define on `nadena.dev.ndmf`. Basis ships
the integration but not NDMF itself, so a project without NDMF builds an empty bundle with only a
logged error.

Not contributed upstream: producing no file is arguably signal enough, and
`BasisAvatarValidator` already warns and offers a one-click removal.

## Later, and what starts each one

Worth building, none of it now. Each names the thing that has to happen first, so none of these
gets picked up early or argued about again.

- **Register the blendshapes a control drives with `BasisBlendshapeBuildHooks`.**
  *Starts when:* the call to `BasisBuildBlendshapeStripper.StripForBuild` in
  `BasisAvatarSDKInspector` stops being commented out.
  The stripper bakes every blendshape outside its keep set into the mesh at its current weight
  and deletes it, and that set is only what `BasisAvatar` names: the fifteen visemes, blink and
  the laughter target. Every shape a converted Vixxy control drives sits outside it, so the
  controls would drive shapes that no longer exist. Nothing subscribes to the hook today.
  Not now because nothing strips, and a registration written now could not be tested against
  anything.

- **Remove the source components from a prefab and its variants.**
  *Starts when:* someone needs to save a converted avatar as a prefab often enough to be worth
  it.
  Unity refuses to save a prefab holding a missing script, which is how VRChat and VRM
  components arrive. `BasisAvatarValidator` already finds them and offers a one-click removal,
  and a scene-only version of ours was built and dropped the same day for matching that scope
  exactly. The version worth having reaches the prefab and its variants and lets the user choose
  which, since the prefab is what cannot be saved while they are on it.

- **Gimmick layers steered by two parameters, and two and four axis puppets.**
  *Starts when:* Vixxy can express two inputs. `HVRVixxyAggregator` cannot today: its body is
  behind `HVR_AGGREGATOR_IS_AVAILABLE`, which nothing defines, its interface base is commented
  out, and the `orchestrator.ProvideValue` it calls does not exist.
